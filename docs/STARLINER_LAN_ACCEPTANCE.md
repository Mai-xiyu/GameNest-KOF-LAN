# Starliner 局域网真人验收清单

本清单只用于 `syedawais10/starliner-game@367f2f33cfff88f6cab6bbd4b6712e2c25aa02cb` 的本地预览适配。至少三名真人、三台独立设备完成全部步骤后，才能记录为地图行动类真人验收；机器人、脚本 WebSocket、同一人多页面和自动化浏览器均不计入人数。

## 前置条件

- 记录测试日期、主机硬件、操作系统、浏览器版本、GameNest 工作树提交／补丁状态和 Starliner 固定上游提交。
- 三台设备连接同一局域网，使用无缓存浏览器；每台设备通过大厅创建自己的平台身份，不共享浏览器资料目录或会话 Cookie。
- 保留局域网互访，同时在路由器或隔离测试网络阻断服务器和三台玩家设备的公网访问。不要只关闭服务器公网而保留玩家设备公网。
- 访问大厅显示的实际 LAN 地址；当前开发机示例为 `http://10.20.55.74:32123/`，IP 变化后必须以启动日志为准。
- Starliner 只能以管理员显式启用的 `preview` 参与测试；不得在验收前改为正式游戏状态。

## 单局闭环

1. 房主从大厅进入 Starliner，创建房间并复制只含 `?room=五位房间码` 的邀请链接。
2. 另外两名玩家分别在独立设备打开邀请链接。记录三台设备显示的不同本人 ID、相同房间码和玩家列表。
3. 房主开局。每名玩家只记录自己页面显示的身份；不得互看屏幕。确认公共玩家快照不显示其他人的真实阵营。
4. 三名玩家分别执行地图移动；至少一名船员完成一个任务。记录任务站、开始时间、完成时间及全局任务计数变化。
5. 破坏者执行一次淘汰。非破坏者尝试发送淘汰动作应无效；出局玩家不得继续移动、任务、报告或投票。
6. 存活玩家移动到尸体附近并报告。远离尸体时的报告尝试应无效。
7. 会议阶段完成公共文字讨论和投票。重复投票、替其他玩家投票及对已出局目标投票应无效。
8. 分别验证频道：存活破坏者阵营消息不被船员接收；存活玩家公共讨论不被出局玩家接收；出局频道不被存活玩家接收。
9. 通过投票、任务或人数条件完成胜负判定。确认结算页显示胜方并可返回统一大厅。
10. 在对应玩家的个人战绩中确认新增 `starliner`、`map-action`、`starliner-adapter-v2`、实际人数、本人阵营和 `casual` 记录；不得进入竞技排行榜。

## 重连与观战反例

1. 行动阶段让一台设备实际断开网络，再恢复局域网并刷新原邀请链接。确认恢复原座位、本人身份、本人角色和已完成任务。
2. 同一身份恢复后，旧页面连接必须失效，不能与新页面同时控制座位。
3. 对局进行中用第四个新身份打开邀请链接，必须被拒绝加入或观战，且不得收到角色、阵营频道、会议状态或终局前非公开信息。
4. 一名玩家返回大厅后再打开原邀请链接，只能恢复自己的座位和角色；不得看到其他玩家身份。
5. 子进程重启会丢失当前内存房间，应显示明确不可恢复状态；不得把平台已保存的历史战绩误当成房间恢复。

## 断公网证据

- 在服务器和三台玩家设备分别确认公网不可达、局域网大厅仍可达；记录验证方法与时间。
- 使用空缓存浏览器重新加载大厅、地图图片、客户端脚本和 WebSocket；不得依赖此前公网缓存。
- 抓取服务器及至少一台玩家设备的连接，确认没有公网 HTTP(S)、STUN 或 TURN 请求。当前静态测试只证明构建产物无显式绝对外链，不能替代此步骤。
- 内置语音保持可选；拒绝麦克风权限或不加入语音时仍必须能够创建房间、开局并完成整局。
